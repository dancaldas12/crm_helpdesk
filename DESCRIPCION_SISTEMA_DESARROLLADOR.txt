# DOCUMENTO DE ARQUITECTURA Y GUÍA TÉCNICA PARA DESARROLLADORES
# SERVICLIENT CRM HELPDESK v1.0.0

================================================================================
1. VISIÓN GENERAL DEL SISTEMA
================================================================================

ServiClient CRM Helpdesk es una plataforma web empresarial diseñada para la gestión
integral de relaciones con clientes (CRM) y soporte post-venta (Helpdesk / Mesa de Ayuda)
en organizaciones B2B (Business-to-Business) que prestan servicios recurrentes.

Objetivos clave:
- Centralizar la gestión de clientes corporativos y contratos de servicios.
- Controlar el ciclo de vida de tickets de soporte con estricto seguimiento de acuerdos de nivel de servicio (SLA).
- Medir la satisfacción del cliente (CSAT) y calcular automáticamente un indicador de salud global (Health Score).
- Prevenir la fuga de clientes (Churn) identificando proactivamente contratos por vencer y cuentas en riesgo.

2. ARQUITECTURA DE SOFTWARE
================================================================================

2.1. Estilo Arquitectónico
--------------------------
- Patrón Arquitectónico: MVC por Capas (Model-View-Controller / N-Tier Architecture).
- Modelo de Datos: Multitenancy Lógico basado en discriminador de empresa (`empresa_id` en todas las tablas transaccionales).
- Renderizado: Server-Side Rendering (SSR) con Spring Boot + Thymeleaf.
- Estilo de Comunicación: HTTP / REST + Formularios web con protección CSRF.
- Documentación viva de APIs: OpenAPI 3.0 (Swagger UI).

4. MÓDULOS DEL SISTEMA
================================================================================

4.1. Módulo de Autenticación y Onboarding de Empresa
- Autenticación: Basada en formulario estándar con Spring Security + BCrypt (12 rondas).
- Wizard de Registro (3 pasos en sesión):
  * Paso 1: Información de la Empresa (Razón social, RUC, industria, país).
  * Paso 2: Usuario Administrador Inicial (Nombre, email corporativo, contraseña).
  * Paso 3: Parámetros del Sistema (Umbrales SLA en horas, escala CSAT, factores Health Score).
- Aislamiento Multitenant: Cada transacción valida el `empresaId` del usuario autenticado.

4.2. Módulo de Gestión de Clientes y Vista 360°
- Listado Paginado: Filtros dinámicos por nombre comercial y estado de salud (`SALUDABLE`, `OBSERVACION`, `EN_RIESGO`).
- Ficha 360° Integral (Tabs):
  * Resumen: KPIs clave (Health Score, CSAT promedio, ARR, días para renovación).
  * Factores de Riesgo: Desglose de penalizaciones detectadas por el motor de salud.
  * Tickets: Historial de solicitudes de soporte asociadas al cliente.
  * Contratos / Renovaciones: Fechas de vencimiento y montos pactados.
  * Contactos: Directorio de tomadores de decisiones y técnicos asignados.
  * Encuestas: Historial de respuestas CSAT con comentarios de clientes.

4.3. Módulo Helpdesk / Mesa de Ayuda y Gestión de SLA
- Ciclo de Vida del Ticket: `ABIERTO` -> `ASIGNADO` -> `EN_PROCESO` -> `PENDIENTE` -> `RESUELTO` -> `CERRADO`.
- Motor de SLA Automatizado:
  * Al crear un ticket, se consulta la tabla `configuracion_sla` según la prioridad (`BAJA`, `MEDIA`, `ALTA`, `CRITICA`).
  * Se calculan los límites temporales exactos: `sla_respuesta_limite` y `sla_resolucion_limite`.
  * Registro de primera respuesta (`primera_respuesta_cumplida`) y tiempo total de resolución.
- Hilo de Conversación Unificado: Soporte para respuestas públicas y notas internas confidenciales.
- Auditoría Integral: Cada cambio de agente, estado o prioridad genera un registro en `ticket_historial`.
- Encuesta CSAT Automática: Al cerrar un ticket, el sistema puede generar un registro en `encuestas_satisfaccion`.

4.4. Módulo de Renovaciones y Retención de Contratos
- Detección Proactiva de Vencimientos: Clasificación por urgencia (<15 días, 16-30 días, 31-60 días).
- Métricas en Tiempo Real: Conteo de contratos por vencer y monto total de ARR en riesgo.
- Bitácora de Seguimientos: Registro de gestiones comerciales y cambio de estado (`EN_NEGOCIACION`, `RENOVADO`, `NO_RENOVADO`).

4.5. Motor de Cálculo de Health Score
El servicio `HealthScoreService` calcula un puntaje de 0 a 100 evaluando 4 pilares:
1. Penalización por Tickets Críticos: Descuento por tickets abiertos con prioridad `CRITICA` o `ALTA`.
2. Cumplimiento de SLA: Penalización si existen tickets que superaron el tiempo límite de resolución.
3. Satisfacción del Cliente (CSAT): Calificación promedio de encuestas recibidas.
4. Urgencia de Renovación: Impacto de contratos próximos a expirar sin seguimiento comercial.
Clasificación resultante:
- [80 - 100]: SALUDABLE (Verde)
- [50 - 79]:  OBSERVACIÓN (Amarillo)
- [0 - 49]:   EN RIESGO (Rojo)

6. CONFIGURACIÓN DE BASE DE DATOS Y PERFILES
================================================================================

6.1. Perfil MySQL (application-mysql.yml)
- Driver: `com.mysql.cj.jdbc.Driver`
- URL: `jdbc:mysql://localhost:3306/serviclient?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=America/Lima&characterEncoding=UTF-8`
- Usuario por defecto: `root`
- Contraseña por defecto: `dcaldas$$` (configurable mediante variable `DB_PASSWORD`)
- Dialecto JPA: `org.hibernate.dialect.MySQLDialect`
- DDL Auto: `update`

6.2. Perfil Default / Testing (application.yml)
- Base de datos: H2 en memoria (`jdbc:h2:mem:serviclientdb`)
- DDL Auto: `create-drop`

7. GUÍA RÁPIDA DE EJECUCIÓN Y COMANDOS MAVEN
================================================================================

7.1. Compilar el proyecto:
  $ mvn clean compile -DskipTests

7.2. Ejecutar la suite de pruebas automatizadas:
  $ mvn clean test

7.3. Levantar la aplicación con MySQL local:
  $ mvn "-Dspring-boot.run.profiles=mysql" spring-boot:run

7.4. Generar el sitio web Javadoc:
  $ mvn javadoc:javadoc -DskipTests
  Ubicación: target/site/apidocs/index.html

7.5. Empaquetar Javadoc en archivo JAR o ZIP:
  $ mvn javadoc:jar -DskipTests
  Ubicación: target/crm-helpdesk-1.0.0-javadoc.jar
  $ Compress-Archive -Path target\site\apidocs\* -DestinationPath target\javadoc-serviclient-crm.zip -Force

7.6. Acceso a interfaces en el navegador:
  * Aplicación Web: http://localhost:8080/
  * Swagger UI:     http://localhost:8080/swagger-ui.html
  * OpenAPI Spec:   http://localhost:8080/v3/api-docs
  * Credenciales:   admin@serviclient.com / admin123
